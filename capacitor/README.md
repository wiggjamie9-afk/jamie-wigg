# RHYTHMIX Capacitor Shell

Wraps the existing RHYTHMIX static site (`index.html`, `rhythmix.html`, etc. at the repo root) as a native iOS/Android app. Bundled offline — no network dependency on `rhythmixapp.com.au`.

- **App ID:** `com.rhythmix.web` (different from the Expo build's `com.rhythmix.app` so both can install side-by-side on the same device)
- **Web bundle:** `capacitor/www/` (regenerated by `npm run build:www`)
- **Capacitor:** v6, no Ionic Framework (your site is already styled)

> ⚠️ Coexists with `mobile/` (Expo). Before publishing, pick one — you don't need both in the stores under similar names.

---

## Setup

```bash
cd capacitor
npm install
npm run build:www          # copies *.html + icons from repo root → capacitor/www/
```

Add a native platform (run once per platform):

```bash
npm run ios:add            # creates capacitor/ios/ (Xcode workspace)
npm run android:add        # creates capacitor/android/ (Gradle project)
```

> Both `ios/` and `android/` directories are gitignored by default in this repo. The moment you write custom native code, drop those entries from `.gitignore` so the changes are tracked.

---

## Iterate

After editing any HTML/CSS/JS at the repo root:

```bash
npm run sync               # rebuilds www/ and pushes into native projects
```

Then open in the native IDE:

```bash
npm run ios:open           # opens Xcode (requires Mac)
npm run android:open       # opens Android Studio
```

Or run on a connected device / emulator:

```bash
npm run ios:run
npm run android:run
```

## Building from an iPhone (no Mac)

Capacitor itself doesn't run cloud builds — you need either:

- **Ionic Appflow** (paid) — Capacitor's first-party cloud build/sign/distribute service. Connects to this repo and produces signed `.ipa` / `.aab` files. https://ionic.io/appflow
- **Codemagic / Bitrise / Expo EAS for Capacitor** — generic CI builders that can also build a Capacitor project. EAS Build supports any React Native / native project, including Capacitor's generated Xcode workspace, but the config is more manual than for the Expo project in `../mobile/`.
- **Borrow a Mac** for one-off `.ipa` builds via Xcode → Archive → Distribute App.

If "iPhone-only, no Mac" is a hard constraint, the Expo path (`../mobile/`) is the lower-friction option. Capacitor wins on offline-bundled web content and tighter integration with your existing static site.

## Updating native plugins

```bash
npm install @capacitor/push-notifications
npm run sync               # picks up the new plugin in iOS/Android
```

Common useful plugins for a RHYTHMIX shell:
- `@capacitor/share` — share a track / playlist via the native share sheet (already installed)
- `@capacitor/browser` — open external URLs in an in-app browser (already installed)
- `@capacitor/haptics` — tap feedback (already installed)
- `@capacitor/push-notifications` — push for launches, new tracks
- `@capacitor/preferences` — local key-value storage
- `@capacitor/filesystem` — write downloaded tracks to disk

## Project layout

```
capacitor/
  capacitor.config.ts      # appId, webDir, plugin config
  package.json
  scripts/
    build-www.sh           # repo-root *.html → capacitor/www/
  www/                     # build output (gitignored)
  ios/                     # Xcode workspace (gitignored — run `cap add ios`)
  android/                 # Gradle project (gitignored — run `cap add android`)
```

## Why both Capacitor *and* Expo in the same repo?

Two different deployments, two different bets. Keeping both for a short comparison period is cheap; you delete the loser when one wins. See `../mobile/README.md` for the Expo alternative.
