# sites/

Landing pages, marketing sites, and microsites generated by the four-stage site build pipeline (Relume-style: sitemap → wireframe → styleguide → design).

## Layout

```
sites/<slug>/
├── sitemap.md            # stage 1: page tree + section list per page (S1, S2, ...)
├── wireframes/
│   ├── home.md           # stage 2: per-page layout intent + suggested copy
│   ├── pricing.md
│   └── ...
├── styleguide.md         # stage 3: color, typography, spacing, components, motion
├── home.html             # stage 4: self-contained rendered HTML
├── pricing.html
└── ...
```

Each `<page>.html` is self-contained: inline `<style>`, inline `<script>`, no build step needed. Preview with:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory sites/<slug>
```

## Pipeline

1. **`/site-sitemap <brief>`** — page tree + section list. Stable section IDs.
2. **`/site-wireframe <slug>`** — per-page layout + suggested copy + component patterns. Multi-page work fans out to parallel `Agent` calls.
3. **`/site-styleguide <slug>`** — visual language. Locked to `rhythmix-teaser-60s/DESIGN.md` for RHYTHMIX work.
4. **`/site-design <slug>`** — render every page to HTML. Multi-page work fans out to parallel `Agent` calls.

Or invoke the orchestrator: **`/site-build <brief>`** runs all four stages sequentially with per-page parallelism inside stages 2 and 4.

For RHYTHMIX work, use **`/rhythmix-site <brief>`** instead — it pre-fills brand-specific clarifying questions and locks the styleguide source.

## File conventions

- **Stable section IDs** — `S1`, `S2`, ... assigned in `sitemap.md`. Wireframes and HTML reference these IDs. Never renumber across regenerations.
- **HTML section element IDs** — `id="s<n>-<slug>"` (e.g. `id="s3-features"`) so DOM traceability matches the wireframe.
- **CSS tokens** — every color and size in the rendered HTML comes from a named `--token` defined in `:root`. The token names come from `styleguide.md`. No magic hex codes in the document body.

## What lives outside this folder

- **RHYTHMIX brand source** — `rhythmix-teaser-60s/DESIGN.md`. Styleguides reference it; they don't duplicate it.
- **Legacy landing fragments** — `text.txt`, `text 2.txt`, `text 3.txt` at the repo root are pre-pipeline HTML/CSS drafts. New work goes in `sites/<slug>/`; the legacy files stay for reference.
- **Live site files** — `rhythmix.html`, `index.html`, `launch-section.html`, etc. at the repo root are the deployed site. `sites/` is for new work that hasn't been promoted yet.
