# Agent TARS experiment

Runbook for validating whether [bytedance/UI-TARS-desktop](https://github.com/bytedance/UI-TARS-desktop)'s Agent TARS CLI is worth integrating into this workspace. Status: **install verified in the Claude Code sandbox, end-to-end run pending on a real desktop**.

## Why

The `slides-skill-author` skill in this repo (`.agents/skills/slides-skill-author/`) produces a `deck-builder` SKILL.md that the user has to paste into claude.ai's Skills UI by hand (Customize → Skills → Create skill → Write skill instructions). Agent TARS is a browser-driving agent that could automate that paste step — and, more generally, any claude.ai UI flow we want to script.

If the experiment works, the next step is a small `agent.config.{json,ts}` plus a `tools/agent-tars/` wrapper so future sessions don't re-derive the command.

## What's been validated in the sandbox

- `npm install -g @agent-tars/cli` succeeds (~815 packages, ~40s, Node 22).
- `agent-tars --help` prints cleanly. v0.3.0.
- CLI subcommands: `serve` (headless server), `run` (interactive / headless), `request` (one-shot LLM), `workspace` (init).
- Key flags for our use case:
  - `--model.provider anthropic --model.id <id>` — Anthropic provider supported.
  - `--browser.cdpEndpoint <url>` — connect to an existing Chrome so we don't have to host claude.ai credentials inside the agent.
  - `--browser.control hybrid|dom|visual-grounding` — visual grounding when DOM isn't enough.
  - `--mcpServer.include / --mcpServer.exclude` — filter MCP servers loaded from the workspace config.

## What couldn't be validated in the sandbox

- No display server, no auto-started Chrome, no `ANTHROPIC_API_KEY`, no way to complete claude.ai's interactive login. The CLI's healthy; the *flow* needs real hardware.

## Prerequisites (on the real desktop)

- Node ≥22.
- Google Chrome (or Chromium) installed.
- An Anthropic API key with budget for Opus.
- A claude.ai account you can log into.

## Runbook

```bash
# 1. Start Chrome with remote debugging on an isolated profile.
#    Use a throwaway --user-data-dir so this Chrome doesn't touch your normal browsing.
google-chrome \
  --remote-debugging-port=9222 \
  --user-data-dir=/tmp/agent-tars-chrome &

# 2. In that Chrome window, log into claude.ai by hand. Once.
#    The session cookie lives in /tmp/agent-tars-chrome so subsequent runs reuse it.

# 3. Install Agent TARS if not already installed.
npm install -g @agent-tars/cli

# 4. Run Agent TARS against that Chrome.
export ANTHROPIC_API_KEY=sk-ant-...
agent-tars run \
  --model.provider anthropic \
  --model.id claude-opus-4-7 \
  --browser.cdpEndpoint http://127.0.0.1:9222/json/version \
  --browser.control hybrid \
  --open
```

`--open` launches the Agent TARS web UI in your default browser. From there:

> Go to claude.ai. Click Customize. Click Skills. Click "Create skill". Click "Write skill instructions". Paste the following content as the Skill instructions and save:
>
> *(paste the deck-builder SKILL.md generated by the `slides-skill-author` skill — see `.agents/skills/slides-skill-author/SKILL.md`)*

## What success looks like

- Agent TARS opens claude.ai in the controlled Chrome.
- It clicks through the Customize → Skills flow without getting stuck.
- The deck-builder skill appears in your claude.ai sidebar after save.
- A follow-up message ("build me a deck about X") triggers the new skill.

## What failure modes to expect

- **Auth wall** — claude.ai signs you out between sessions or hits a CAPTCHA. Cookies in `/tmp/agent-tars-chrome` should survive normal expiry, but Cloudflare-class challenges will block the agent.
- **DOM drift** — claude.ai is a React app with non-semantic class names. If Agent TARS can't find a button via the DOM, it falls back to visual grounding. Visual grounding burns more tokens and is slower.
- **Anthropic provider mismatch** — Agent TARS shipped 0.3.0 in Nov 2025 with Claude 3.7 Sonnet listed. `claude-opus-4-7` may or may not be wired up; if it errors with "unknown model", fall back to `claude-sonnet-4-6` and report the gap upstream.
- **Token cost** — each "click this button" loop is a full multimodal call. A 7-step skill setup is probably $0.50–$2 of Opus.

## After the experiment

If the deck-builder upload works end-to-end, in this repo:

1. Add `agent.config.json` at the repo root mirroring `.mcp.json` — so Agent TARS sees the `creative-stack`, `higgsfield`, `pollinations` MCP servers. Note: Agent TARS uses its own config schema, not Claude Code's. Translate, don't symlink.
2. Add `tools/agent-tars/run.sh` wrapping the command above with sane defaults.
3. Add a `.agents/skills/agent-tars/SKILL.md` so Claude Code can trigger Agent TARS for browser tasks where MCP servers aren't enough.

If the experiment fails, write down which step broke and where, and decide whether the failure is a 0.3.0 bug worth filing upstream or a fundamental claude.ai-bot-detection problem (the latter would kill the project for our use case).

```bash
npm uninstall -g @agent-tars/cli
rm -rf /tmp/agent-tars-chrome
```
